# VPN DNS Guard 0.1.0

Лёгкая DNS-блокировка для **уже работающего AmneziaWG/WireGuard в Docker**.
Строгий режим: сбой AdGuard или остановка контроллера не открывает выход к
публичным DNS. Конфигурации клиентов, VPN-ключи и существующие маршруты не меняются.

## Что поддерживается

- Ubuntu 24.04 LTS, системный Python 3.12, amd64 или arm64, systemd.
- Работающий Docker Engine и WG/AWG-контейнеры с одним IPv4-туннелем каждый.
- Общая IPv4 Docker bridge-сеть для доступа к DNS на её шлюзе.
- Уже установленные `docker`, `ip`, `ss`, `nft`, `systemctl`, `systemd-analyze`,
  `useradd`, `getent`, `runuser`, `chown`. Пакет не запускает `apt upgrade` и
  не устанавливает Amnezia. Недостающие зависимости перечисляет `check`.

Автоопределение ищет интерфейсы `awg0`, `wg0` и аналогичные внутри работающих
контейнеров Amnezia/WireGuard. Другие Amnezia-компоненты пропускаются.
При неоднозначной сети укажите `--network ИМЯ_СЕТИ`; установщик не угадывает.

**Установка поверх другого AdGuard запрещена по умолчанию.** В том числе пакет
обнаруживает ранее созданные `codex-adguardhome.service`. Действующий сервер
с такой установкой не нужно переустанавливать этим архивом. Автоматической
миграции старой индивидуальной конфигурации в версии 0.1 нет.

## Установка из архива

Команды выполняются владельцем в серверной консоли с административными правами.
Сначала перенесите архив и соответствующий `.sha256` на сервер.

```sh
sha256sum -c vpn-dns-guard-v0.1.0.tar.gz.sha256
tar -xzf vpn-dns-guard-v0.1.0.tar.gz && sh vpn-dns-guard/install.sh
```

Для отдельной проверки перед установкой:

```sh
sh vpn-dns-guard/vpn-dns-guard check
```

В установленной системе доступна команда `vpn-dns-guard`:

```sh
vpn-dns-guard status
vpn-dns-guard doctor
```

Первая установка скачивает официальный AdGuard Home **v0.107.79**, проверяет
закреплённую SHA256 и извлекает только бинарный файл. Сам AdGuard не включён в архив.
Если GitHub недоступен, заранее скачайте соответствующий официальный архив:

```sh
sh vpn-dns-guard/install.sh --offline-archive /путь/AdGuardHome_linux_amd64.tar.gz
```

Проверка SHA256 всё равно обязательна. Опции отключения проверки нет.

## Установка из GitHub-релиза

На новом подходящем сервере, в консоли владельца с административными правами:

```sh
curl -fsSLo bootstrap.sh https://raw.githubusercontent.com/Dron2837/vpn-dns-guard/v0.1.0/bootstrap.sh
sh bootstrap.sh Dron2837/vpn-dns-guard v0.1.0
```

Исходники: <https://github.com/Dron2837/vpn-dns-guard>.
Версионный пакет: <https://github.com/Dron2837/vpn-dns-guard/releases/tag/v0.1.0>.
Bootstrap скачивает архив и его SHA256, проверяет имена/типы файлов, затем
запускает установщик. Нельзя указывать `latest`. Для собственного форка замените
в командах владельца и репозиторий. Private GitHub Release требует отдельного
способа доставки: встроенного хранения токенов в bootstrap нет.

## Встроенные списки

По умолчанию включены **77 правил доменов с поддоменами**:

| Группа | Правила | Содержимое |
|---|---:|---|
| `services` | 67 | Выбранные домены Яндекса, VK, Mail.ru, ОК, Дзена, Rutube, MAX |
| `banks` | 9 | Основные домены Сбера, ВТБ, Альфа-Банка, Т-Банка |
| `gosuslugi` | 1 | Госуслуги, включая `esia.gosuslugi.ru` |

Это политика ограничения доступа, **не список доказанных участников обнаружения
VPN**. Списки не гарантируют охват каждого нового домена или API сервисов.
Блокировка банков и ЕСИА может затронуть вход через эти сервисы на других сайтах.

При установке можно выбрать группы:

```sh
sh vpn-dns-guard/install.sh --groups services,gosuslugi
```

Свои правила и исключения:

```sh
vpn-dns-guard block add example.ru
vpn-dns-guard block remove example.ru
vpn-dns-guard allow add example.org
vpn-dns-guard allow remove example.org
```

`allow add` разрешает домен даже при блокировке во встроенном списке. Правила
AdGuard вне управляемого блока сохраняются. Политика меняется через локальный API,
без перезапуска служб. Перед изменением создаётся закрытая резервная копия.

`vpn-dns-guard update-lists` **повторно применяет списки из установленного пакета**.
Команда не загружает неограниченный внешний список. Для новой версии встроенных
списков нужен проверенный новый выпуск пакета; миграции версий в 0.1 не автоматизированы.

## Сеть и строгий режим

1. DNS AdGuard слушает только IPv4-шлюз выбранной Docker-сети, UDP/TCP 53.
2. Панель слушает только `127.0.0.1:3000` или следующий свободный порт до 3099.
3. В каждом обнаруженном VPN-контейнере создаётся только собственная NAT-цепочка
   `VDNS_DNS`, на которую направляются DNS-пакеты из его туннеля/подсети.
4. Отдельная таблица `inet vpn_dns_guard` запрещает прямой выход DNS из обнаруженных
   Docker-мостов и их IPv4-подсетей. Это также закрывает промежуток после перезапуска
   контейнера, пока его собственная цепочка не восстановлена.
5. Супервизор проверяет состояние раз в 30 секунд и восстанавливает свои цепочки.
   При смене IP контейнера в той же сети обновляет разрешённые DNS-клиенты.
6. Проверка `ExecStartPre` в **собственном drop-in Docker** загружает защиту перед
   будущим запуском Docker. Если она не загрузится, этот запуск Docker завершится
   ошибкой. Сам установщик Docker не перезапускает.

Правила запрета применяются к DNS из **всех контейнеров на обнаруженных мостах**,
а не только к двум текущим VPN-процессам. Используйте пакет на выделенном VPN-VPS;
другим приложениям в тех же Docker-сетях может понадобиться настройка DNS.

При недоступности AdGuard новые DNS-запросы клиентов не получат ответа. Публичный
DNS автоматически не разрешается. Остановка монитора/его служб не удаляет правила.
Для возврата к прежнему DNS требуется явное удаление ниже.

Установщик не очищает чужие firewall-таблицы, не изменяет `/etc/resolv.conf`,
не отключает `systemd-resolved`, не меняет SSH и VPN-конфигурации и не перезапускает
Docker, VPN, сетевые службы или сервер. Перезапускаться при сбое может только
добавленная им собственная служба.

## Панель и пароль

```sh
vpn-dns-guard credentials
```

Показывает случайный пароль только владельцу в консоли. Не отправляйте вывод в
публичные issues или логи CI. Панель открывается через SSH-туннель, например:

```sh
ssh -N -L 3000:127.0.0.1:3000 USER@SERVER
```

Адрес и порт уточните через `status`. В браузере своего компьютера откройте
`http://127.0.0.1:3000`. Пользователь панели — `admin`.

## Сбой установки и откат

После неполной установки сохраните вывод и повторите **ту же команду install**.
Состояние хранится по этапам, чужие объекты не перезаписываются; дублирование
правил и маркеров не допускается. Установленная строгая защита остаётся включённой
при ошибках. Если зависимость/топология изменилась, сначала устраните причину.

Резервная копия по запросу:

```sh
vpn-dns-guard backup
```

Явный возврат к старому DNS и отключение пакетных служб:

```sh
vpn-dns-guard uninstall --restore-dns
```

**Эта команда намеренно отключает фильтрацию и открывает прежний DNS-путь.**
Удаляются только собственные цепочки, таблица, units и Docker drop-in. Данные,
резервные копии, служебная учётная запись и файлы программы сохраняются.

Основные пути: `/opt/vpn-dns-guard`, `/var/lib/vpn-dns-guard`,
`/var/lib/vpn-dns-guard-admin` (доступ только root), `/var/backups/vpn-dns-guard`.

## Ресурсы и границы

Кэш DNS 4 МиБ; журналы запросов и статистика выключены; служебный журнал AdGuard
ротируется по 5 МБ с двумя копиями. Лимит AdGuard — 192 МиБ, супервизора — 96 МиБ;
это максимумы, не обещание фактического расхода. Для установки требуется минимум
256 МиБ доступной RAM и 512 МиБ свободного диска. Swap автоматически не создаётся.

Пакет фильтрует **обычный DNS внутри обнаруженных IPv4 VPN-туннелей**. Ответы A/AAAA
фильтруются, но собственный DoH приложений, прямые IP-соединения, сохранённые IP,
трафик из клиентских исключений VPN и активные соединения этим не блокируются.
IPv6 DNS-серверы клиентов не перенаправляются; выход обычного DNS из охваченных
мостов блокируется и для IPv6. Изменение подсетей, имён/типов туннелей или сетей
требует повторной проверки; автоматическая миграция в другую топологию не обещается.
Не гарантируются анонимность VPN или защита его IP от блокировок.
