# Проверка пакета

## Автоматические тесты без административных прав

```sh
python3 -m unittest discover -s tests -v
python3 build_release.py
```

Тесты моделируют Docker/iptables/nft/systemd в отдельном временном дереве файлов.
Они не изменяют реальные сетевые правила или службы. HTTP-тест поднимает только
временный loopback-сервер и проверяет ответы JSON, обычный `OK` и пустой ответ.

Покрываются: автоопределение нескольких туннелей/сетей, пропуск других компонентов
Amnezia, конфликт DNS-портов, строгий отказ DNS, потеря NAT-правил при пересоздании,
смена IP контейнера, ACL, повторный install, восстановление прерванной установки,
идемпотентность списков, белый список, повреждённые маркеры, частичный отказ API,
явное удаление собственных объектов, сохранение чужих правил, отсутствие restart
Docker/VPN и отсутствие автоматического открытия DNS при остановке монитора.

Моделирование не заменяет испытание на настоящем ядре Linux. Workflow
`privileged-integration.yml` предназначен для ручного запуска на одноразовом
GitHub Actions Ubuntu 24.04 runner. Он не должен запускаться на рабочем VPS.

## Перед эксплуатацией нового выпуска

Изолированная проверка настоящего официального бинарного файла:

```sh
python3 tests/native_smoke.py /путь/к/AdGuardHome
```

Используйте закреплённую версию и проверьте SHA256 архива из `release.json`.
Тест запускает временный процесс от текущего пользователя, только на loopback
и свободных высоких портах, затем завершает его и удаляет временные файлы.
Проверяются вход с паролем, начальная фильтрация, реальный блокирующий UDP-ответ,
выключенные журналы запросов и статистика. Сетевые правила не изменяются.

1. Запустить unit-тесты и сборку; сверить воспроизводимость SHA256 архива.
2. Запустить ручной privileged workflow на изолированном runner.
3. Проверить реальное перенаправление UDP/TCP DNS от двух тестовых туннелей,
   блокирующие A/AAAA-ответы и обычные домены.
4. Остановить только тестовый AdGuard: запрос к публичному DNS должен перестать
   работать, внешний DNS нельзя разрешать как fallback.
5. Проверить перезапуск тестового контейнера и повторную установку без дублей.
6. Выполнить явное удаление: исходный DNS должен восстановиться, чужие правила
   должны сохраниться.

Чистая установка на новом VPS, реальный отказ службы и реальный перезапуск Docker
не испытываются на рабочем сервере пользователя. Результаты сборки поставляются
отдельно в отчёте; наличие workflow не означает, что он уже был выполнен.
